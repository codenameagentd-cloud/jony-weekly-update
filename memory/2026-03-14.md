## [Discord #weekly-report-editor] Editor 修復 + Preview Panel (16:53-17:04)
- **JS 外洩根因找到**：`buildStandaloneHTML` 的 backtick template literal (line 603-670) 包含 `<body>`, `</head>`, `<script>`, `</style>` 等 raw HTML tags，瀏覽器 parser 把它們當真的 tag 解析，破壞頁面結構
- **修法**：用 hex escape (`\x2F`, `\x73`, `\x62`) 替換 template literal 內所有 HTML tags
- **驗證**：本地瀏覽器確認 scrollHeight=900、script display:none、零 JS 外洩
- **教訓**：`grep -c` 數 script tag 不夠！tag 數量平衡不代表瀏覽器解析正確。Template literal 裡的 HTML tags 會被瀏覽器 parser 誤解析。以後所有 JS template literal 裡的 HTML 結構 tags 都必須 hex escape。
- **David 要 preview 放出來**：加了右側 inline preview panel，Generate 後 slides 直接顯示在右邊
- 佈局改成三欄：Editor | Settings sidebar | Preview panel

### 學到的教訓

**1. 文案是主角，設計是載體**
- 第一版 Others 頁把文案砍太多，David 說「失去重點」
- 正確做法：完整保留原文，用排版（pull quote、分段、divider）創造層次，不是刪減

**2. 左文右圖是安全的 editorial 佈局**
- 文案放左（主導閱讀動線），視覺素材放右（輔助理解）
- 反過來放會讓人先看圖再找文字，不適合內容密集的 status report

**3. 不要替 David 做產品決策**
- 加了 "try the generator" 按鈕 → David 說產品還沒準備好
- 學習：功能展示 ≠ 邀請使用，report 裡只呈現事實和進度

**4. Pull quote 提煉核心觀點很有效**
- 每頁用一句話大字抓住結論 → 正文展開 context
- 這是 editorial design 的核心手法：headline carries the argument

**5. 數據視覺化要克制**
- Progress 頁用大數字 + 進度條就夠了，不需要圖表
- Status report 的數據量不大，簡單直接比花俏有效

**6. Mobile responsive 要一開始就做**
- 不要等 David 在手機上看到問題才加
- 以後每個新模板：桌面做完 → 立刻加 responsive → 再交付

**7. 保持原設計不動**
- David 多次強調「封面不要動」「不要影響原本設計」
- responsive 只加 @media，不改原有 CSS
- 新功能用增量方式加，不重寫

### 可升級到 TOOLS.md 的規則
- Status report 排版：左文右圖、pull quote 提煉、數據克制
- 文案完整性 > 視覺簡潔性（不要為了設計砍文案）
